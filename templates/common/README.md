# Common pack

Files every project gets, whatever its stack. `/kit:new` lays them down with a stack pack on top; `/kit:adopt` offers them to an existing repo one group at a time. `plugins/kit/scripts/apply_template.py` does the copying and never overwrites a file.

## Files
| File | What it does | What it assumes |
|---|---|---|
| `CLAUDE.md.template` | The project's CLAUDE.md: what it is, layout, repo rules, module skills, docs, gates, compact instructions. The stack's `CLAUDE.md.template` goes under it. About 30 lines, so the whole file stays under 150 | The bootstrap replaces every `<!-- fill: ... -->` marker |
| `README.md.template` | The project's README.md: what it is, run it, check it, read next | Same |
| `docs/README.md` | The docs index, grouped by reader | Every doc under `docs/` gets a line |
| `docs/decisions/0001-record-architecture-decisions.md` | ADR: why decisions are ADRs, in MADR 4 minimal style | The bootstrap sets `date` and `decision-makers` |
| `docs/decisions/0002-choose-the-stack-and-hosting.md` | ADR to fill in: the stack and hosting, and why | Same, plus the options and reasons |
| `docs/runbooks/deploy.md` | Deploy, verify and roll back, to fill in | |
| `docs/api/README.md` | The API overview: the generated schema, the conventions, how the API changes. Kept when the API has external consumers or a mobile app; otherwise the bootstrap deletes `docs/api/` and its index lines | `docs/api/openapi.yaml` is generated by the stack |
| `docs/api/handoffs/_template.md` | The shape of a per-feature handoff, by operationId. Copied to `handoffs/<feature>.md`; the template itself keeps its markers | |
| `gitignore.additions` | Lines for `.gitignore`: env files except `.env.example`, Claude Code's local files and worktrees, archify output, `*.tsbuildinfo`, the handoff note | Becomes `.gitignore`, or is appended to an existing one |
| `.env.example` | The convention: every variable the code reads, secrets empty, optional ones commented out. Stack packs replace it with their own list | |
| `lefthook.yml` | Pre-commit: Betterleaks on the staged diff, a block on `.env*` (not `.env.example`), `.claude/settings.local.json` and key files, and a warning past about 600 changed lines (lockfiles and migrations aside). Commit-msg: lowercase Conventional Commit of at most 72 characters, no co-author or AI attribution lines. It extends `.lefthook/*.yml`, where each stack pack adds its lint and format jobs | lefthook 2.x, `betterleaks` on `PATH` |
| `kit.json` | The base of `.claude/kit.json`: `gate.review.min_lines` 50 and an empty `docs.allowed`. The stack adds `gate.journeys`; `apply_template.py` sets `stack` | |
| `.markdownlint-cli2.jsonc` | markdownlint's defaults, minus line length, blank lines around headings, lists, tables and code blocks, and padded table separators, none of which the kit's docs use | |
| `.ls-lint.yml` | kebab-case names under `docs/`, `NNNN-title.md` ADRs, `_template.md` in the handoffs | |
| `.github/workflows/docs.yml` | `scripts/docs-check.py`, markdownlint-cli2, lychee in offline mode (links inside the repo only) and ls-lint | Actions pinned by SHA |
| `scripts/docs-check.py` | Checks the docs standard (below). Stdlib only, Python 3.11 or later | `scripts/docnames.py` beside it |
| `scripts/docnames.py` | The docs naming rules `docs-check.py` reads: which `docs/` folders have a naming rule, and what makes a scratch, versioned or dated name. The kit's docs location guard reads the same file, so the two judge a name alike | |

## Special names
Besides the three in `templates/README.md` (`README.md`, `kit.json`, `CLAUDE.md.template`), the common pack uses:

| Template file | In the project |
|---|---|
| `README.md.template` | `README.md`, written from the answers |
| `gitignore.additions` | `.gitignore`: a new file gets every line; an existing one gets the lines it lacks (`append` in `apply_template.py`'s output) |
| `.lefthook/<stack>.yml` (in a stack pack) | Copied as is; `lefthook.yml` picks it up through `extends` |

## docs-check.py
`python3 scripts/docs-check.py [--root DIR]` exits 1 and lists each problem as `path: what is wrong and what to do`:
- `README.md`, `CLAUDE.md`, `docs/README.md`, `docs/runbooks/deploy.md` and at least one ADR exist; CLAUDE.md has at most 150 lines.
- Markdown lives at the root (`README`, `CLAUDE`, `AGENTS`, `CHANGELOG`, `SECURITY`, `CONTRIBUTING`, `LICENSE`), as a `README.md` anywhere, under `.claude/` or `.github/`, in `docs/` as the docs rule lays it out (`decisions/`, `runbooks/`, `architecture/`, `api/`, `api/handoffs/`, `partners/`, `guides/`), or under a `docs.allowed` glob in `.claude/kit.json`. Dependency, build and fixture folders are skipped.
- Names carry no `v2` or `round3` part and no date. Files in the `docs/` folders are kebab-case, and ADRs are `NNNN-kebab-title.md`; there that naming rule decides, so a subject may hold a scratch word, as in `docs/runbooks/fix-stuck-queue.md`. Anywhere else a name carries no scratch word (summary, report, notes, plan, fix, status, progress, todo, remaining, findings, analysis, final, latest, reply). The rules live in `scripts/docnames.py`.
- `docs/README.md` links every doc under `docs/`, inline or by reference.
- ADRs have front matter with `status`, `date` (YYYY-MM-DD) and `decision-makers`, a title, and the MADR headings in order.
- Outside ADRs and the CHANGELOG, prose has no dates and no history words (`previously`, `as of`, `used to be`, "it used to"); fenced and inline code are skipped. Module skills are checked too.
- A `docs.ignore` glob in `.claude/kit.json` drops matching paths from every check above, not just where they're allowed to live; use it for paths that document or test something other than this repo's own docs, such as vendored or template content.
- No `<!-- fill: ... -->` marker is left, except in the handoff template.
- Every variable the code reads through `os.environ`, `os.getenv`, django-environ's `env(...)`, `process.env` or `import.meta.env` is in `.env.example`, set or commented out. Runtime names such as `NODE_ENV`, `CI` and Vite's built-ins are skipped. A variable read only through a parsed object, such as `schema.parse(process.env)`, isn't seen.

## How it was checked
With the kit's tests (`plugins/kit/tests/test_docs_check.py`, `test_apply_template.py`), and on a scratch repo holding these files: lefthook 2.1.15 validated the config, accepted a conventional commit, rejected a non-conventional subject and a co-author line, warned on a 700-line commit and stayed quiet on 1,400 lines of lockfile and migration; Betterleaks 1.9.0 ran on the staged diff; markdownlint-cli2 0.23.3, lychee 0.24.2 (`--offline`) and ls-lint 2.3.1 passed on the skeleton; actionlint 1.7.12 passed the workflow. The workflow hasn't run on GitHub.
